## Технический план frontend (user-часть) для "Мини-облако"

### 1. Общая архитектура и стек

- **Стек:**
  - Next.js 16 (App Router)
  - React 19
  - TypeScript
  - Tailwind CSS (light/dark mode)
  - TanStack Query (React Query) для работы с API
  - Библиотека для модалок (можно кастомно на базе headless UI-паттернов)
- **Принципы:**
  - Чёткое разделение: слои API-клиента, бизнес-логики (hooks/сервисы), UI-компонентов.
  - Модульность: фронтенд разделён на доменные модули (`auth`, `files`, `sharing`, `quota` и т.п.), общие UI-компоненты переиспользуются, бизнес-логика не смешивается с разметкой, минимум хардкода, конфигурация через env (`NEXT_PUBLIC_API_BASE_URL` и др.).
  - JWT в `localStorage`, передача в `Authorization: Bearer ...`.
  - Стиль и UX — ориентир на Google Drive: плиточный вид, современный UI, удобная работа с файлами.

---

### 2. Страницы и маршруты

- **Основные маршруты:**
  - `/login` — страница входа.
  - `/signup` (опционально, если не делаем отдельную форму, можно объединить с `/login`, но по плану логичнее разнести) — регистрация.
  - `/files` — главная страница файлового менеджера (после логина).
  - `/files/[...path]` — вложенные папки (динамический сегмент для иерархии).
  - `/shared/[token]` — публичная страница доступа по ссылке (без авторизации).

- **Маршрутизация и редиректы:**
  - Если пользователь не авторизован (нет валидного токена) и пытается попасть на `/files` или дочерние — редирект на `/login`.
  - Если авторизован и приходит на `/login` — редирект на `/files`.

- **Макеты (layouts):**
  - `app/(auth)/login` и `app/(auth)/signup` — layout без боковых панелей, минималистичный.
  - `app/(app)/files` — layout с:
    - верхней панелью (логотип/название, поиск, переключатель темы, логин/логаут, индикатор квоты);
    - левым сайдбаром (дерево папок, быстрые фильтры, квота).

---

### 3. Состояние приложения и инфраструктура

- **Auth слой:**
  - `AuthContext`/hook `useAuth`:
    - хранит: токен, данные пользователя (id, username, assigned/used space).
    - методы: `login`, `logout`, `refreshUser`.
  - Инициализация на клиенте:
    - при загрузке приложения читаем JWT из `localStorage`;
    - при его наличии запрашиваем `/api/auth/me` для актуальных данных.

- **API-клиент:**
  - Модуль `apiClient`:
    - базовый URL берётся из `NEXT_PUBLIC_API_BASE_URL`;
    - перехватчик добавляет `Authorization` с токеном;
    - обработка 401 для авто-логаута/редиректа на `/login`.
  - Обёртки для основных доменов:
    - `authApi`, `filesApi`, `foldersApi`, `shareApi`, `quotaApi`.

- **React Query:**
  - Настроить общий `QueryClientProvider` в корневом layout.
  - Ключи кэша:
    - `["folders", folderId]`, `["files", folderId]`,
    - `["quota", userId]`,
    - `["share", token]`.

---

### 4. UI файлового менеджера (как Google Drive)

- **Основная структура страницы `/files` / `/files/[...path]`:**
  - Верхняя панель:
    - логотип / название,
    - поиск (по имени файла/папки),
    - индикатор квоты,
    - переключатель темы (light/dark),
    - аватар/иконка пользователя с меню (`Профиль`, `Выйти`).
  - Левый сайдбар:
    - дерево папок (корневые, вложенные);
    - быстрые фильтры (в дальнейшем: "Мои файлы", "Изображения", "Видео").
  - Основная область:
    - toolbar сверху:
      - кнопка "Новая папка",
      - кнопка "Загрузить" (открывает выбор файла),
      - зона drag&drop.
    - область контента:
      - плиточный/grid вид файлов и папок (карточки с иконкой, именем, размером, датой).

- **Поддерживаемые операции в MVP (UI):**
  - Папки:
    - создать,
    - открыть,
    - удалить.
  - Файлы:
    - загрузить (через input и drag&drop),
    - открыть (просмотр / запуск превью),
    - скачать,
    - удалить,
    - “поделиться”.
  - Переименование/перемещение — можно заложить в дизайн, но реализовать позже.

---

### 5. Загрузка файлов и drag&drop

- **Компоненты:**
  - `UploadZone`:
    - поддержка drag&drop (подсветка области при перетаскивании),
    - отображение состояния (idle, uploading, error).
  - `UploadList`:
    - список текущих загрузок с прогресс-барами.

- **Поведение:**
  - При выборе файлов или drop:
    - по каждому файлу отправляем `POST /api/files/upload` (multipart).
    - отправляем `folderId` текущей папки (если есть).
  - Отображение прогресса:
    - использовать `onUploadProgress` (если axios) или кастомный прогресс с запросом размера.
  - После успешной загрузки:
    - инвалидация кэша `["files", currentFolderId]` и `["quota", userId]`.

---

### 6. Превью файлов (модалки)

- **Общий компонент `FilePreviewModal`:**
  - Открывается при клике на файл.
  - Внутри — выбор конкретного viewer’а в зависимости от `mimeType`.
  - Общие элементы:
    - заголовок (имя файла),
    - кнопки: “Скачать”, “Закрыть”.

- **Типы файлов:**
  - Изображения:
    - `img` или `next/image` с URL `/api/files/{id}/preview`.
    - Масштабирование под экран, фон затемнён.
  - Видео:
    - `<video controls>` с `src` на `/api/files/{id}/preview` или `/download` (backend обеспечит поддержку range-запросов для удобного просмотра).
  - Текстовые:
    - запрос содержимого (например, через `/preview` с text/plain),
    - отображение в красивом скроллируемом блоке (`<pre>`/`<code>` с моноширинным шрифтом).
  - Офисные документы / прочие:
    - если браузер умеет встроенно показывать (PDF, некоторые форматы) — можно использовать `<iframe>` с URL,
    - иначе выводим сообщение “Этот формат не поддерживается для предпросмотра” + кнопку “Скачать”.

---

### 7. Механизм “поделиться” на фронтенде

- **Создание ссылки:**
  - Контекстное меню/иконка “Поделиться” у файла/папки.
  - Модалка `ShareModal`:
    - выбор TTL (radio-кнопки: 1 час, 24 часа, 7 дней, 30 дней),
    - кнопка “Создать ссылку”.
  - После `POST /api/share`:
    - отображение сгенерированного URL,
    - кнопка “Скопировать” (используем `navigator.clipboard`).

- **Работа по публичной ссылке `/shared/[token]`:**
  - При заходе:
    - запрос `GET /api/share/{token}`.
    - если токен невалиден/просрочен — показать аккуратную страницу с ошибкой (“Ссылка недействительна или устарела”).
  - Если объект — файл:
    - показываем превью (если поддерживается) + кнопка “Скачать”.
  - Если объект — папка:
    - показываем список файлов/подпапок (упрощённый файловый менеджер, только просмотр/скачивание, без редактирования).

### 8. Квота и сортировки

- **Индикатор квоты:**
  - Полоска прогресса в верхней панели или сайдбаре:
    - текст: “X из Y ГБ использовано”.
    - цветовая индикация при превышении порогов (например, >80% — оранжевый, >90% — красный).

- **Сортировки и фильтры:**
  - В toolbar списка файлов:
    - выпадающий список сортировки: по имени, размеру, дате (вверх/вниз).
  - Реализация:
    - либо на фронте (если backend отдаёт полный список),
    - либо через параметры в запросах (опция на будущее).

### 9. Темы (light/dark) и язык

- **Темы:**
  - Tailwind: `dark`-класс на `html`/`body`.
  - Переключатель темы в верхнем баре (иконка солнце/луна).
  - Хранение предпочтения (localStorage: `theme = "light" | "dark" | "system"`).

- **Язык:**
  - Интерфейс на русском.
  - Текстовые строки вынести в отдельный модуль `i18n/ru.ts` или простой объект констант для удобной правки.

---

### 10. Обработка ошибок и состояния

- **Ошибки API:**
  - Глобальный компонент `ErrorModal`/сервис:
    - для отображения ошибок (квота превышена, нет доступа, ошибка сервера).
  - Общие сценарии:
    - 401 — сброс auth-состояния и редирект на `/login`.
    - 403 — модалка “Нет доступа”.
    - 413/квота — модалка “Превышен лимит дискового пространства”.

- **Offline / проблемы с backend:**
  - При сетевой ошибке показывать баннер/модалку “Проблемы с сетью или сервером. Попробуйте позже”.
  - Можно добавить кнопку “Повторить запрос”.

- **Loading-состояния:**
  - Skeleton/спиннеры:
    - при загрузке списка файлов,
    - при открытии превью,
    - при входе/регистрации.

### 11. Связь с брейкпоинтами backend (F1/F2/F3)

- **F1 — старт frontend (auth + каркас файлового менеджера):**
  - Требования от backend:
    - реализованы `Auth API` (`/api/auth/signup`, `/api/auth/login`, `/api/auth/me`),
    - базовая модель пользователя.
  - На frontend реализуем:
    - страницы `/login`, `/signup`,
    - auth-контекст, хранение токена,
    - базовый layout `/files` (без реальных данных, заглушки).

- **F2 — работа с файлами и папками:**
  - Требования от backend:
    - `File & Folder API`, квоты (`QuotaService`) — шаги 4–5 backend-плана.
  - На frontend добавляем:
    - загрузку файлов (drag&drop + input),
    - просмотр списка папок/файлов, сортировки,
    - превью файлов (изображения/видео/текст),
    - индикатор квоты.

- **F3 — шаринг:**
  - Требования от backend:
    - `Share API` (шаг 6 backend-плана),
    - публичный доступ по токену.
  - На frontend добавляем:
    - модалку “Поделиться” и генерацию ссылок,
    - страницу `/shared/[token]` с просмотром и скачиванием.
